## C. Incompatible (requires refactor / explicit new design)

| #   | File · Symbol                                           | Observed behavior                                                                                                                                                          | Why it blocks / what must change                                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | `app/(app)/layout.tsx`                                  | Calls `resolveCurrentHousehold()`; **`if (!current) redirect("/onboarding")`** — every authenticated user without an active household is forced into household onboarding. | **Central blocker.** A provider-only user (no household) would be bounced into household onboarding and never reach provider screens. Post-login routing must become workspace-aware (ADR-1). `(app)` layout itself can stay household-scoped once routing no longer funnels everyone through it. |
| C2  | `household_activity_events`, `notifications`            | `household_id uuid NOT NULL` on both (append-only envelopes).                                                                                                              | Provider events have no household. Cannot insert. Need `provider_activity_events` (own table, no `household_id`) and a decision on whether provider in-app notifications reuse `notifications` (requires nullable/scope change) or a new table — ADR-3 / ADR-15.                                  |
| C3  | `users.active_household_id`/`preferred_household_id`    | FK → `households(id)`.                                                                                                                                                     | Cannot point at a provider. Workspace persistence requires new column(s)/table — ADR-1.                                                                                                                                                                                                           |
| C4  | `idempotency_keys` PK `(household_id, idempotency_key)` | Hard household scope.                                                                                                                                                      | Provider-scoped idempotency cannot key on household. Generalize scope columns — ADR-10.                                                                                                                                                                                                           |
